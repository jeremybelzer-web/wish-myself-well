# The curiosity database

Everything the app knows how to look at, in one place, at four levels. Every item can be switched on and off
(a key, a button, a MIDI note) and every slider inside it can be automated (from, to, curve, then a knob, an
LFO or a MIDI control moves it).

| Level | What it is | Its sliders |
| --- | --- | --- |
| Curiosity | A lens on one aspect of a scene (music, wardrobe, shot size) | Its own graded sliders, plus Amount |
| Suite | A few curiosities looked through together | Blend, a weight per member, Amount |
| Proximity | When X happens, Y tends to follow within some beats | Cause, Delay, How often, Effect size, Amount |
| Proximity suite | A few proximities that act together | Blend, a delay and a how-often per member, Amount |

A slider is either a **scale** of words in order (`floor, low, eye, high, overhead`) or a **range** of numbers
(`0 to 100 %`). A scale with no natural order (which track, which Enneagram type) is marked `unordered` and
its default curve is `steps`. Every slider carries `from`, `to` and `curve` (`linear`, `ease`, `in`, `out`,
`steps`, the same curves as `automation.js`).

Every item has a plain-language description and a `workspace` (its main tab), plus `also` (other tabs it
shows up in). The 22 workspaces in `workspaces.js` (including the lens workspaces Wardrobe, Color, Set design,
Emotion, Emotional road, Comedy and Comedy from the mix) are all here; three more are new and marked
`proposed`: Music & sound, Editing & structure, Page & panel.

**The app's `lenses.js` and this database.** `lenses.js` (from the app thread) defines the color, wardrobe, set,
emotion, emotional road, comedy and comedy-from-the-mix lenses. The importer reads it row for row, with the
same ids, and the other data files add sliders to its lens rows (for example `mainEra` gains loudness, layers,
accessories, hair and makeup, true to them, and change since last scene) rather than making second copies.
New lens rows should go in one place: send them to the database thread, or add them to `lenses.js` and re-run
`node data/tools/import-catalog.js`.

## Files

| File | What is in it |
| --- | --- |
| `curiosity-db.js` | The database itself: adders, lookups, `check()`, and the functions the app calls |
| `db-workspaces.js` | The workspaces |
| `db-catalog.js` | Every existing curiosity, suite, proximity and proximity suite from `catalog.js`, `library.js`, `story-curiosities.js`, `lenses.js`, `model.js` and `automation.js`. Generated by `tools/import-catalog.js`; do not hand-edit |
| `db-catalog-sliders.js` | Extra sliders for the catalog rows (merged into them by id) |
| `db-music.js` | Music, no music, sound around the scene |
| `db-emotion.js` | More sliders for the Emotion and Emotional road lenses, the feeling gap between characters, emotion suites and proximities |
| `db-comedy.js` | More sliders for the Comedy lenses, plus one curiosity per comic device with no row yet (running gags, callbacks, rule of three, slapstick, wordplay, misdirection, irony, understatement, visual gags, comic editing and sound), comedy suites and proximities |
| `db-design.js` | More sliders for the wardrobe and set lenses, props, wardrobe and set suites and proximities |
| `db-look.js` | More sliders for the Color lens, a Lighting lens, color and light suites and proximities |
| `db-character.js` | The character matrix (draft PR #6): 18 axes, Enneagram health, dramatic role, the nine type patterns, stress and growth arrows. Generated by `tools/import-character-matrix.js` |
| `db-proximity-words.js` | Plain "When ..., ..." halves for proximities named another way ("Pride before a fall") |
| `db-model-scenes.js` | Eight made-up scenes written as beat-by-beat traces (a diner standoff, a meet-cute, a dinner party, a dark hallway, a montage, a deadpan office, a quiet goodbye, a kitchen disaster), so the Prism and Study views have films to split. Not real films |
| `model-scenes.studies.json` | Those scenes as a file the Study tab's Import button reads. Written by `check-db.js` |
| `db-finish.js` | Loaded last: any row still holding only its setting gets "how noticeable" and "how it changes" |
| `files.json` | The load order |
| `check-db.js`, `load-db.js` | `node data/check-db.js` checks every row and link and writes `curiosity-db.json` |
| `curiosity-db.json` | The whole database as JSON, for other tools (Maya panel, desktop app, VCV module) |

A later file can add sliders to an earlier row by using the same id: new sliders are added, and fields named in
`override` (such as `workspace` or `plain`) replace the earlier ones.

## How the app loads it

The app thread ("Bring Maya into the app") owns `index.html` and the app code. To switch the database on:

1. In `index.html`, after `model.js` and before `automation.js`, load the files in the order of `files.json`,
   then hand the database the app's lists (they are top-level consts, so pass them in):

   ```html
   <script src="data/curiosity-db.js"></script>
   <script src="data/db-workspaces.js"></script>
   <script src="data/db-catalog.js"></script>
   <script src="data/db-catalog-sliders.js"></script>
   <script src="data/db-music.js"></script>
   <script src="data/db-emotion.js"></script>
   <script src="data/db-comedy.js"></script>
   <script src="data/db-design.js"></script>
   <script src="data/db-look.js"></script>
   <script src="data/db-character.js"></script>
   <script src="data/db-proximity-words.js"></script>
   <script src="data/db-model-scenes.js"></script>
   <script src="data/db-finish.js"></script>
   <script>CuriosityDB.install({ CURIOSITIES, SUITES, PROXIMITIES });</script>
   ```

   `install` adds every curiosity the app lacks to `CURIOSITIES` (in catalog.js's shape), plus one row per lens
   slider with the id `<curiosity>.<slider>` (for example `music.tempo`), adds the new suites and proximities,
   and adds every lens's sliders to `window.CURIOSITY_FACETS`, which `automation.js` already turns into lanes.
   Existing rows are left alone.

2. That is all automation needs, as long as `install` runs before `automation.js`. If it ever runs later,
   call `CuriosityDB.installAutomation(window.CurioAuto)` after it.

3. The model scenes can be offered as curated films: `CuriosityDB.studiesExport().studies` is a list in
   study.js's shape (id, title, kind, beats with values). Until the app adds them, anyone can load them with the
   Study tab's Import button and `data/model-scenes.studies.json`. Tested: with them loaded, the Prism splits
   "Talk in a diner turns into a standoff" into 41 curiosities and 6 proximities that held, including "When the
   music is cut dead, a big line lands" (2 of 6 times).

4. Workspaces can read their lists from the database instead of keeping their own:
   `CuriosityDB.forWorkspace("music")` returns `{ curiosities, suites, proximities, proximitySuites }`.
   `CuriosityDB.data.workspaces` lists every workspace with its label, scope and plain description.

Tested on 2026-10-02 by loading a copy of `index.html` with those lines in headless Chromium: no page errors;
`CurioAuto` had 1,123 parameters, `c:music` had 18 lanes, and `c:mainEra` had its 8 lenses.js lanes plus the
database's 6. Slider rows carry `sliderOf: "<lens id>"`, so the All curiosities list can hide them under their
lens (otherwise it grows from about 240 rows to about 790).

## Checking

```sh
node apps/curiosities/data/check-db.js
```

It fails (exit code 1) and lists the problems if any item has no description, an unknown workspace, a slider
that is not graded, a from or to off its scale, or a suite, proximity or proximity suite that points at
something that does not exist. When it passes it rewrites `curiosity-db.json`.

## Rules carried over

- Studies of real films store counts and ids only. The database names devices and settings, never a scene's
  script or shot list.
- The nine Enneagram patterns and the comedy and music settings are first drafts written for this app; Jeremy
  and Sharani can rename or drop any row.
